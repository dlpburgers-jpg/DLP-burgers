# Sellos DLP

Reglas autorizadas: una hamburguesa comprada suma un sello al entregar; las unidades gratis y los starters no suman. Premios opcionales de 5 sellos por envío (mínimo 3 hamburguesas), 10 por un starter y 20 por una hamburguesa Simple. Cada canje descuenta su costo; un beneficio por pedido. Los extras pagos no son parte del premio.

La conversión inicial usa floor(max(0,puntos)/1000) por cliente. El remanente se descarta del saldo utilizable, pero los movimientos anteriores y el registro del cálculo se conservan. No repetir la migración ops/loyalty-stamps.sql. Los pedidos anteriores aún pendientes acreditan hamburguesas al entregarse; no se vuelven a acreditar pedidos históricos ya completados.

El botón de canje genera un código UUID vinculado al titular y al premio. Generarlo no cobra sellos: se descuentan al confirmar el pedido. Las solicitudes repetidas recuperan el mismo código pendiente. El servidor valida titular, saldo, premio, productos y entrega, consume el código en la misma transacción del pedido y devuelve sellos ante cancelación sin duplicaciones. No es un cupón transferible. Los datos de códigos y movimientos tienen RLS y no permiten acceso directo a clientes.

La tarjeta contiene 20 logos, a color para el saldo disponible y grises para el resto. El saldo total continúa visible aunque supere 20. El producto se elige antes de generar el código; se abre su configuración para completar opciones del menú. El descuento se incorpora al total confirmado.

Validación: pruebas de conversión, elegibilidad y acreditación; pruebas SQL transaccionales con rollback para permisos, códigos repetidos, reuso bloqueado, cobro, acreditación sin la burger gratis, devolución, starter y delivery (dos rechazadas / tres aceptadas). Suite del proyecto: 172 pruebas. QA de interfaz con datos y códigos ficticios; sin pedidos persistidos ni mensajes enviados.

Las apps nativas requieren distribuir una nueva compilación para mostrar estas reglas. Las versiones anteriores no pueden canjear con costos viejos: deben generar un código desde la interfaz nueva. No restaurar el sistema de puntos anterior sobre saldos convertidos sin una conciliación del historial de sellos.
